## Overview

This tool processes enterprise `.docx` documents and replaces all detected Personally Identifiable Information (PII) with **realistic, consistent fake data** generated by the [Faker](https://faker.readthedocs.io/) library. The replacement is **deterministic** — if `"Rashi Patil"` appears in 15 places, it is replaced by the same fake name (e.g., `"Margaret Johnson"`) everywhere, preserving document coherence while eliminating privacy risk.

The engine **strictly preserves** all original formatting — bold, italic, font sizes, colours, table structures, headers, and footers are untouched.

## Architecture & Hybrid Approach

The detection layer uses a **hybrid NLP + pattern** strategy:

```
┌─────────────────────────────────────────────────────────────┐
│                   DETECTION LAYER                           │
│                                                             │
│  ┌──────────────────┐    ┌──────────────────────────────┐   │
│  │  spaCy NER Model │    │  Presidio Pattern Recognizers │   │
│  │  (en_core_web_lg)│    │  (Regex + Context Keywords)   │   │
│  │                  │    │                              │   │
│  │  • PERSON        │    │  • US_SSN                    │   │
│  │  • ORGANIZATION  │    │  • CREDIT_CARD               │   │
│  │  • GPE/ADDRESS   │    │  • DATE_OF_BIRTH             │   │
│  │                  │    │  • EMAIL_ADDRESS              │   │
│  │                  │    │  • PHONE_NUMBER               │   │
│  │                  │    │  • IP_ADDRESS                 │   │
│  │                  │    │  • ADDRESS (street patterns)  │   │
│  │                  │    │  • ORGANIZATION (suffixes)    │   │
│  └──────┬───────────┘    └──────────────┬───────────────┘   │
│         │                               │                   │
│         └──────────┬────────────────────┘                   │
│                    ▼                                        │
│         ┌──────────────────┐                                │
│         │ Overlap Resolver │ ← keeps highest-confidence     │
│         └────────┬─────────┘                                │
│                  ▼                                          │
│         ┌──────────────────┐                                │
│         │ Confidence Filter│ ← threshold = 0.35            │
│         └────────┬─────────┘                                │
└──────────────────┼──────────────────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────────────────┐
│                 REPLACEMENT LAYER                            │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │              ConsistentMapper (Faker)                  │  │
│  │                                                        │  │
│  │  "Rashi Patil"     → "Margaret Johnson"  (PERSON)     │  │
│  │  "rp@acme.com"     → "jdoe@example.net"  (EMAIL)     │  │
│  │  "Acme Corp"       → "TechNova LLC"      (ORG)       │  │
│  │                                                        │  │
│  │  Deterministic: same input always → same output        │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
                   ▼
┌──────────────────────────────────────────────────────────────┐
│               DOCX PROCESSOR                                 │
│                                                              │
│  • Walks paragraphs, headers, footers, tables, nested tables │
│  • Replaces text at the run level (preserves formatting)     │
│  • Saves the output .docx with identical layout              │
└──────────────────────────────────────────────────────────────┘
```

### Why Hybrid?

| Approach | Strength | Weakness |
|---|---|---|
| **spaCy NER alone** | Excellent at names, orgs, locations from context | Cannot detect structured patterns like SSNs, credit cards, IPs |
| **Regex alone** | Perfect for structured patterns (SSN, CC, email) | Cannot detect context-dependent entities like names or company names |
| **Hybrid (this tool)** | Combines both: NER for contextual entities, regex for structured patterns | Slight overhead from running both engines; requires overlap resolution |

The hybrid approach ensures **maximum recall** (catching both structured and unstructured PII) while the confidence threshold and overlap resolver maintain **precision**.

## Supported PII Types

| Entity Type | Detection Method | Faker Generator |
|---|---|---|
| `PERSON` | spaCy NER | `faker.name()` |
| `EMAIL_ADDRESS` | Presidio built-in regex | `faker.email()` |
| `PHONE_NUMBER` | Presidio built-in regex | `faker.phone_number()` |
| `ORGANIZATION` | spaCy NER + custom suffix patterns | `faker.company()` |
| `ADDRESS` | spaCy GPE + custom street-address regex | `faker.address()` |
| `US_SSN` | Presidio built-in regex | `faker.ssn()` |
| `CREDIT_CARD` | Presidio built-in regex | `faker.credit_card_number()` |
| `DATE_OF_BIRTH` | Custom multi-format date regex + context | `faker.date_of_birth()` |
| `IP_ADDRESS` | Presidio built-in regex | `faker.ipv4()` |

## Installation

```bash
# 1. Clone the repository
git clone <repo-url> && cd pii-redaction-engine

# 2. Create a virtual environment (recommended)
python -m venv .venv && source .venv/bin/activate

# 3. Install dependencies
pip install python-docx presidio-analyzer presidio-anonymizer spacy faker

# 4. Download the spaCy language model
python -m spacy download en_core_web_lg
# (Falls back to en_core_web_sm automatically if en_core_web_lg is unavailable)
```

### Requirements

- Python ≥ 3.9
- See `requirements.txt` for pinned versions

```bash
python redact_pii.py --input contract.docx --output contract_redacted.docx
```

### With Evaluation

```bash
python redact_pii.py \
  --input contract.docx \
  --output contract_redacted.docx \
  --ground-truth annotations.json \
  --evaluate
```

### Save the Mapping Dictionary

```bash
python redact_pii.py \
  --input contract.docx \
  --output contract_redacted.docx \
  --mapping-output pii_map.json
```

### Adjust Confidence Threshold

```bash
# Higher threshold = fewer false positives, more false negatives
python redact_pii.py -i input.docx -o output.docx --threshold 0.6

# Lower threshold = more aggressive detection
python redact_pii.py -i input.docx -o output.docx --threshold 0.2
```

## Engineering Tradeoffs

### 1. Confidence Threshold (default: 0.35)

| Setting | Effect |
|---|---|
| **Lower (0.1–0.3)** | Higher recall but more false positives — generic words like "Order", "Service" may be flagged as ORG |
| **Default (0.35)** | Balanced for enterprise documents |
| **Higher (0.5–0.8)** | Higher precision but some PII may be missed, especially informal names or partial addresses |

**Decision**: We defaulted to 0.35 because in privacy-sensitive contexts, **missing PII (false negative) is more damaging** than over-redacting (false positive). Users can tune via `--threshold`.

### 2. Run-Level vs. Paragraph-Level Replacement

- **Paragraph-level** is simpler but destroys all formatting (every run collapses into one).
- **Run-level** (our approach) is more complex — it must redistribute characters across variable-length runs when a replacement differs in length from the original.
- **Decision**: We chose run-level to guarantee **zero formatting loss**, which is critical for legal/enterprise documents.

### 3. Overlap Resolution Strategy

When spaCy and a regex recognizer both flag overlapping spans:
- We keep the detection with the **higher confidence score**.
- On a tie, we keep the **longer span** (more context = more accurate).
- **Decision**: This prevents double-replacement artifacts (e.g., replacing a name inside an already-replaced email).

### 4. spaCy Model Size

- `en_core_web_lg` (≈560 MB) provides significantly better NER accuracy than `en_core_web_sm` (≈12 MB).
- **Decision**: Default to `lg` with automatic fallback to `sm`. The trade-off is disk space and load time vs. detection quality.

### 5. Deterministic Faker Seed

- A fixed seed (`FAKER_SEED = 42`) produces repeatable fake data across runs, aiding in testing and auditing.
- **Decision**: Fixed seed by default; set `FAKER_SEED = None` in the source for random generation in production.

## Known False Positives & False Negatives

### Observed False Positives

| Scenario | Entity Type | Example | Cause |
|---|---|---|---|
| Generic business terms | `ORGANIZATION` | "Order", "Service Agreement" | spaCy misclassifies capitalised common nouns as ORG |
| Section headings | `PERSON` | "Summary", "Appendix A" | spaCy's NER interprets capitalised words as names |
| Numeric identifiers | `PHONE_NUMBER` | "Order #1234567890" | 10-digit sequences match phone number patterns |
| Date-like values | `DATE_OF_BIRTH` | Contract dates (e.g., "01/15/2024") | Date regex has no semantic context to distinguish contract dates from DOBs |
| Internal reference codes | `CREDIT_CARD` | 16-digit internal reference numbers | Luhn-valid 16-digit numbers match CC patterns |

### Observed False Negatives

| Scenario | Entity Type | Example | Cause |
|---|---|---|---|
| Unusual name formats | `PERSON` | "van der Berg", "O'Malley-Smith" | spaCy may not recognise hyphenated / prefixed names |
| Non-US phone formats | `PHONE_NUMBER` | "+91 98765 43210" | Presidio's default phone patterns are US-centric |
| PO Box addresses | `ADDRESS` | "P.O. Box 1234, Springfield" | Street-address regex does not cover PO Box format |
| Abbreviated SSNs | `US_SSN` | "SSN: ***-**-1234" | Partially masked SSNs don't match full SSN pattern |
| Names in tables | `PERSON` | Names split across table cells | Each cell is analysed independently; context is lost |

### Mitigation Strategies

1. **Expand context keywords** for custom recognizers to reduce FPs.
2. **Add deny-list patterns** (e.g., "Order", "Agreement") to suppress known FPs.
3. **Add PO Box and international phone regex patterns** for better recall.
4. **Pre-process table cells** by concatenating adjacent cells for context-aware analysis.

## Evaluation Framework

The built-in evaluation module compares detections against a **ground-truth annotation file** (JSON format):

```json
{
  "full_text": "Rashi Patil works at Acme Corp. Her SSN is 123-45-6789.",
  "annotations": [
    {"start": 0,  "end": 12, "entity_type": "PERSON",       "text": "Rashi Patil"},
    {"start": 22, "end": 31, "entity_type": "ORGANIZATION",  "text": "Acme Corp"},
    {"start": 44, "end": 55, "entity_type": "US_SSN",        "text": "123-45-6789"}
  ]
}
```

### Matching Criteria

A detection is a **True Positive** if:
- Its character span overlaps ≥ 50% (IoU) with a ground-truth annotation, **AND**
- The `entity_type` matches.

This tolerates minor boundary differences (e.g., capturing a trailing space).

### Metrics

| Metric | Formula |
|---|---|
| **Precision** | TP / (TP + FP) |
| **Recall** | TP / (TP + FN) |
| **F1 Score** | 2 × (P × R) / (P + R) |
| **Accuracy** | (TP + TN) / (TP + TN + FP + FN) |

## Extending the Engine

Adding a new PII type requires changes in **three** clearly marked locations:

### Step 1: Register the Entity Type

```python
# In SUPPORTED_PII_TYPES list:
SUPPORTED_PII_TYPES.append("PASSPORT_NUMBER")
```

### Step 2: Add a Presidio Recognizer

```python
# In _build_analyzer():
passport_recognizer = PatternRecognizer(
    supported_entity="PASSPORT_NUMBER",
    patterns=[Pattern("US_PASSPORT", r"\b[A-Z]\d{8}\b", 0.7)],
    supported_language="en",
    context=["passport", "travel document"],
)
analyzer.registry.add_recognizer(passport_recognizer)
```

### Step 3: Add a Faker Generator

```python
# In ConsistentMapper._generate():
"PASSPORT_NUMBER": self._gen_passport,

# New method:
def _gen_passport(self) -> str:
    return f"{self._faker.random_uppercase_letter()}{self._faker.random_number(digits=8)}"
```
